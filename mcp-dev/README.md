# Wallet MCP 接入验证

这个目录在现有 Wallet 仓库中提供独立测试 Worker。首次初始化时，虚拟账户有 100.00 元人民币。每笔测试支出限 0.01 至 10.00 元。工具仅接受金额（整数分）、预期版本和操作 UUID。现有 PWA 没有引用此目录，测试服务也没有读取手机备份、localStorage 或生产账本的入口。

## 本地复现

在 Node.js 22 或更高版本中运行以下命令。测试在本机启动 Workers 运行时和独立的临时 D1、KV，自动生成测试密钥并在结束时清理临时数据。

```sh
cd mcp-dev
npm ci
npm test
```

测试通过 HTTP 执行 OAuth 发现、动态客户端注册、浏览器授权和 PKCE S256 换取令牌，再用官方 MCP SDK 客户端执行 initialize、列出工具、查询、写入和新会话读回。1.23 元支出的结果与原站 `js/calc.js` 对照。另覆盖只读越权、错误密钥、来源校验、同版本并发、重试、撤销、令牌过期、服务重启和所有者密钥轮换。

## 独立测试部署

先核实该账户的 Workers 套餐和 D1、KV 免费容量。仅操作本项目新建的专用资源。保留现有 PWA 的托管地址、缓存版本和仓库默认分支。这个 Worker 限定 `wallet-mcp-dev.<子域>.workers.dev`，不包含自动部署流程。

1. 在确认的免费账户创建 D1 `wallet-db-dev`、KV `wallet-oauth-dev` 和 Worker `wallet-mcp-dev`。在新建的空测试 D1 执行 `schema.sql`。重复执行会保留测试记录。
2. `npm run build` 生成 Worker ES 模块 `dist/worker.mjs`。使用模块模式，兼容日期 `2026-07-01`，兼容标志 `global_fetch_strictly_public`。关闭 Workers Logs、调用日志和持久化调试采样。仅启用这个开发 Worker 的 workers.dev 地址，关闭版本预览 URL。
3. 绑定 D1 为 `DB`、KV 为 `OAUTH_KV`；为此测试项目选独立命名空间的限流绑定 `LIMITER`，建议每个来源每分钟 60 次。设置文本变量 `ISSUER` 为 Worker 的完整 HTTPS 源（不含末尾斜杠）。
4. 打开此开发 Worker 的 `/setup-key`，点“生成并选中密钥”，将本机生成的密钥保存在密码管理器中；也可以直接用密码管理器生成 32 字节随机密钥，格式为 64 位小写十六进制。通过 Cloudflare 控制台的加密 Secret 字段写入该 Worker 的 `OWNER_KEY`。授权时仅在自己这个 Worker 的 HTTPS 页面输入。在聊天、Git、命令参数或普通环境变量中粘贴密钥会暴露它。密钥格式错误或缺失时，授权和持凭证的账本操作返回 503，公开的 OAuth 发现地址仍可读取。
5. 先向 `/mcp` 发起无凭证请求，预期 401 和 OAuth 发现地址。验证发现元数据中的 issuer、resource 及回调；只有应用管理页显示的回调与实现允许的 ChatGPT 稳定回调完全一致时再授权。出现不同回调，先核实文档、调整精确匹配并重跑测试。
6. 在 ChatGPT 网页的 Plugins → + → Add custom MCP server 中创建个人连接。Server URL 填开发 Worker 的 `/mcp`，选择 OAuth 和动态客户端注册。安装到个人账户，按提示授权。只读工具使用 `wallet:read`，写工具另需 `wallet:write`。令牌有效期 15 分钟，到期重新授权。

## 普通聊天和手机验收

同一个测试插件在网页普通聊天和 iOS 普通聊天分别跑一遍。各端使用不同的新操作 ID。Work 或 SDK 成功只能填写对应一行。

| 位置 | 操作 | 预期 |
| --- | --- | --- |
| 网页普通聊天 | 调用插件查虚拟余额和版本；明确要求记一笔 1.23 元虚拟支出；新聊天读回 | 余额减少 123 分，版本增加 1 |
| iOS 普通聊天 | 先读回网页写入后的余额；明确记一笔 0.77 元虚拟支出；回到网页查询 | 两端看到同一收据对应的最终余额和版本 |
| 只读授权 | 在只有读取权限时请求写入 | 收到权限挑战；完成写授权前余额和版本保持原值 |
| 重试及冲突 | 相同参数和操作 ID 重发；然后以旧版本和新 ID 调用 | 重发返回原收据，旧版本返回冲突 |

新建测试库从 100.00 元开始，上述两笔后的预期余额依次为 98.77 和 98.00 元。重复练习从当时的余额计算。可记录平台、工具名、金额、版本和错误类别；保密所有授权码、请求头及密钥。

## 关闭与撤销

移除 ChatGPT 个人插件连接。协议支持在授权服务器公布的 revocation_endpoint 撤销令牌。KV 的跨区域撤销传播有延迟，令牌另受 15 分钟到期时间限制。需要关闭服务时，停用该测试 Worker 的 workers.dev 入口。轮换或移除 `OWNER_KEY` 后，更新配置生效的实例将拒绝旧授权。D1 数据保留，便于核对收据。删除测试资源会销毁数据，需要单独确认。

## 接下来何时开始同步

iOS 普通聊天已完成虚拟读写，网页普通聊天单独跟踪。开发分支的业务数据库以整数分保存账户余额。`business-schema.sql` 和 `business-ledger.js` 的本地 D1 测试用独立期初余额核对支出、收入、退款、转账、同版本竞争、原请求重试和分页读回。运行 `npm test` 可复现。

### 手机虚拟同步预览

独立的 `wallet-sync-dev` Worker 提供原 Wallet 页面和离线资源。它没有数据库绑定或密钥。进入「我的 → 虚拟账本同步 → 连接虚拟账本」，在现有开发授权站点授权。手机和 ChatGPT 各自取得短期凭证，共用虚拟现金账本。预览只传金额、操作 ID 与预期版本。流水备注和分类留在本机，预览关闭了备份导入入口。

虚拟支出限 0.01 至 10 元。联网、回前台和手动刷新会拉取云端收据并处理待同步队列；离线时，本机流水和待同步记录一次保存。遇到版本冲突会保留待同步记录，供所有者在同步页确认。断开授权保留本机数据。预览仅使用测试站点的存储，与原 GitHub Pages 账本隔离。

运行 `npm test` 构建两个 Worker 并验证权限、离线重开、回执丢失、重试与冲突。使用全新的虚拟浏览器账本验证过原页面的离线快捷记账 0.77 元，另一个 MCP 客户端记 1.23 元，两端最终读到 98.00 元、版本 2。手机虚拟预览与生产业务账本的迁移是两个独立步骤。真实数据首次同步仍需确认处理范围、迁移预览和正式上线。
